hash values can be a simple FNV-1a hex from your file generator (offline tool you run before packaging).

On file://: the loader will not attempt fetch() the file to compute hash (browsers block it), but will keep the manifest available for human reference and for checksum attempts on http(s) when possible.

Lightweight checksum (no library)

Use a tiny FNV-1a hash implementation inline in the failsafe (few lines):

function fnv1a(str) {
  let h = 2166136261 >>> 0;
  for (let i = 0; i < str.length; i++) {
    h ^= str.charCodeAt(i);
    h = Math.imul(h, 16777619) >>> 0;
  }
  return ('0000000' + h.toString(16)).slice(-8);
}


Use this only when you can read the script text (inline script tags or if fetch() available).

If unavailable, mark checksum attempt as “skipped (file:// environment)”.

Root-cause heuristics (how root is chosen)

Critical asset failure (script/CSS failed to load) → highest priority. If asset is in DIAG_MANIFEST.critical, mark fatal.

Checksum mismatch (when available) → next priority — suggests cache corruption.

Uncaught exception originating from a module that failed earlier → correlated and promoted.

Worker/Promise rejection that occurs during boot → mid priority.

Watchdog expiration without visible errors → lower priority; show last pushStep() events.

Multiple low-priority warnings → show grouped; suggest “partial functionality”.

Each event is scored; the highest score becomes the root cause shown in the UI top summary.

Enterprise blocking: your code will not perform any network sends; export is user-initiated download (safe). That avoids Sophos/Cyberhaven DLP flags.

No new libs: all hashing, parsing, and UI must be inlined or added as plain JS files you control.
